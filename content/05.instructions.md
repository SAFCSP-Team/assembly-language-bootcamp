# Assembly Language Instructions

An **instruction** in assembly language is a fundamental command that tells your computer’s processor exactly what to do. These instructions are the building blocks of all computer programs.

## What Are Instructions?

Each **instruction** in assembly language is a single operation that the CPU can perform. These instructions are translated directly into machine code.

**Types of instructions:**
- **Data manipulation** (move, copy, modify values)
- **Program flow control** (jump, call, return)
- **Hardware interaction** (input, output)

### Basic Structure

Each instruction generally has two main parts:
- **Mnemonic**: The short name for the operation (e.g., `MOV` for "move," `SUB` for "subtract").
- **Operands**: The values or locations the instruction works on (e.g., registers, memory addresses, constants)

> [!IMPORTANT]
> Assembly mnemonics are **not case-sensitive**: `MOV` and `mov` are the same.


## Instruction Syntax

Assembly instructions generally follow this format for **x86 architecture**:

```
MNEMONIC  OPERAND1, OPERAND2   ; Optional Comments
```
- **Mnemonic/Operation/Opcode**: The command you want the computer to perform (for example, `MOV` to move data, `ADD` to add numbers).
- **Operands:** The data or locations involved (e.g., registers, memory addresses, constants).On **x86**, the first operand is generally the **destination**, and the second is the **source**.
- **Comments**: Begins with `;` and are ignored by the assembler. 

> [!IMPORTANT]
> This is the syntax for **x86**. The order of operands (source, destination) and the specific mnemonics may **differ by CPU architecture** (e.g., x86, ARM, MIPS, RISC-V).  

#### Guidelines
- Only **one instruction per line**.
- Use **commas** to separate operands.
- Use whitespace (spaces/tabs) for readability.
- Use **comments** to explain your code.
- **Assembler directives (such as `.data`) are not instructions**. They guide the assembler, not the CPU.

#### Example

Suppose your data section includes:
```asm
.data
a   dw 10      ; 2-byte variable 'a' initialized to 10
b   dw 0       ; 2-byte variable 'b' initialized to 0
```
You can write:
```asm
MOV  b, a      ; Copy the value of 'a' into 'b'
```

## Registers
**Registers** are **small, fast storage locations** within the central processing unit (CPU) that are **used in nearly every assembly instruction**. 

You can think of them as specialized "containers" that the processor uses to hold data temporarily while performing calculations.

### Common 32-bit x86 Registers
In 32-bit assembly (like x86), some commonly used registers are:

| Name | Typical Use          | Description                                |
|------|---------------------|--------------------------------------------|
| EAX  | Accumulator         | General-purpose, often used for results    |
| EBX  | Base                | General-purpose, often used for addressing |
| ECX  | Counter             | Often used for loops/counting              |
| EDX  | Data                | General-purpose, often used for data operations |
| ESI  | Source Index        | Used in memory copy operations             |
| EDI  | Destination Index   | Used in memory copy operations             |
| ESP  | Stack Pointer       | Points to top of the stack                 |
| EBP  | Base Pointer        | Stack frames for function calls            |

- Registers are named beginning with **E** for “extended” (because they hold 32 bits).
- Each register can hold just one value at a time.

#### Example
```asm
MOV EAX, 10      ; Store 10 in EAX
MOV ECX, EAX     ; Copy value of EAX to ECX
```
After these instructions, both EAX and ECX contain the value 10.


## Common Assembly Instructions

### Data Movement Instructions

These copy or transfer data between registers, memory, or constants.

#### Guidelines
- Both operands cannot be memory addresses.
- Operand sizes must match.

#### `MOV` : Move Data
Copies data from the source to the destination.

```asm
MOV EAX, EBX          ; Copy EBX to EAX
MOV EAX, 1            ; Store 1 into EAX
```

#### `LEA` : Load Effective Address
Loads a memory address (not value) into a register.

```asm
LEA ESI, [myArray]    ; ESI gets the address of myArray
```

#### `XCHG` : Exchange
Swaps values between two registers, or register and memory.

```asm
XCHG EAX, EDX        ; Swap values of EAX and EDX
```


### Arithmetic Instructions

Used for arithmetic calculations in your programs.

#### `ADD` : Add Values   
Adds source to destination.

```asm
ADD EAX, 100          ; EAX = EAX + 100
```

#### `SUB` : Subtract Values  
Subtracts source from destination.

```asm
SUB EBX, EAX          ; EBX = EBX - EAX
```

#### `INC` : Increment the Value 
Increases the value by 1.

```asm
INC ECX               ; ECX = ECX + 1
```

#### `DEC` : Decrement the Value 
Decreases the value by 1.

```asm
DEC EDX               ; EDX = EDX - 1
```

#### `MUL` / `IMUL` : Multiply Two Values 
- `MUL` for unsigned multiplication.
- `IMUL` for signed multiplication.

```asm
MUL EBX               ; Multiply EAX * EBX (unsigned)
IMUL EDX              ; Multiply EAX * EDX (signed)
```

> [!NOTE]
> In x86 assembly, multiplication and division instructions use a pair of registers to store the result because the result can be larger than a single register:
> - The result of multiplication (e.g., `EAX * EBX`) spans **64 bits**:   
>   - **EAX** holds the lower 32 bits  
>   - **EDX** holds the upper 32 bits
>   
> This example only shows the basic usage. For the large result, check both registers. 
> #### Don't forget that other architectures may use different registers or conventions.

#### `DIV` / `IDIV` : Divide Two Values
- `DIV` for unsigned division.
- `IDIV` for signed division.

```asm
DIV ECX               ; EAX / ECX (unsigned)
; EAX = quotient, EDX = remainder

IDIV ECX              ; EAX / ECX (signed)
; EAX = quotient, EDX = remainder
```

> [!NOTE]
> For division in x86, both the quotient and remainder are produced:  
> - **EAX** holds the quotient  
> - **EDX** holds the remainder  
> - The dividend is actually the full value of **EDX:EAX** (EDX is the high 32 bits, EAX the low 32 bits), which is divided by the operand.
>     
> This example only shows the basic usage. For more complex operations, manage both registers appropriately.


### Logical Instructions
Operate on bits within registers or memory.

#### `AND` : Bitwise AND

```asm
AND EAX, 0FFH      ; Clear high 3 bytes of EAX
```

#### `OR` : Bitwise OR

```asm
OR EAX, EBX        ; Bitwise OR between EAX and EBX
```

#### `XOR` : Bitwise Exclusive OR

```asm
XOR EDX, EDX       ; Zero out EDX
```

#### `NOT` : Bitwise NOT

```asm
NOT ECX            ; Invert all bits in ECX
```


### Comparison Instruction

#### `CMP` : Compare Values 
Subtracts source from destination, updates CPU flags, **but does not store the result**.

```asm
CMP EAX, EBX          ; Set CPU flags as if EAX - EBX
```


## Instruction Encoding 

Assemblers translate assembly instructions into binary **machine code** for the CPU. This process is called **encoding**.

**Key concepts:**
- **Opcode**: Specifies the operation.
- **Operands**: Identify registers, memory, or constants.
- **Instruction length**: A single assembly instruction can take up multiple bytes of machine code, depending on its complexity, operand types, and addressing modes.

#### Example
| Assembly         | Machine Code (x86) | Meaning                        |
|------------------|-------------------|---------------------------------|
| `MOV EAX, EBX`   | `89 D8`           | Copy EBX into EAX               |
| `ADD EAX, 1`     | `83 C0 01`        | Add 1 to EAX                    |

> [!Note]
> While you usually don't write machine code directly, understanding encoding helps with debugging and performance.

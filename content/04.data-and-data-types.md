# Data and Data Types

Understanding how data is represented and managed in assembly language is critical for writing effective programs. This topic covers what data is, the main data types, and how to declare and use data within your assembly code.

## What is Data in Assembly Language?
**Data** refers to the raw values your program processes and manipulates, such as numbers, characters, memory addresses, or even program instructions. In assembly language, you have direct control over how data is stored and handled in memory, making correct data management essential for reliable programs.

## Common Data Types in Assembly Language
Most assembly languages (like x86 and ARM) support a core set of data types

### Byte
- **Size:** 8 bits (1 byte)
- **Range:** 0 to 255 (unsigned), -128 to 127 (signed)
- **Usage:** Single characters, small numbers

### Word
- **Size:** 16 bits (2 bytes)
- **Range:** 0 to 65,535 (unsigned), -32,768 to 32,767 (signed)
- **Usage:** Short integers, addresses (on some CPUs)

### Double Word (Dword)
- **Size:** 32 bits (4 bytes)
- **Range:** 0 to 4,294,967,295 (unsigned), -2,147,483,648 to 2,147,483,647 (signed)
- **Usage:** Standard integer size on many modern CPUs


## Why Do Data Types Matter?

Choosing the right data type in assembly is important because it allows you to:

- Allocate the appropriate amount of memory
- Interpret stored values correctly (e.g., signed vs. unsigned)
- Interact properly with the operating system and other programs.

Incorrect data type usage can result in bugs, misinterpreted values, or memory errors.


## Signed and Unsigned
**Signed** and **unsigned** values use the same storage size, but differ in how they are interpreted:
- **Unsigned numbers** can only represent non-negative values (zero and positive numbers).  

**Example**
```asm
section .data
    unsigned_byte   db  255                ; 8-bit unsigned value
    unsigned_word   dw  65535              ; 16-bit unsigned value
```  

- **Signed numbers** can represent both positive and negative values.

**Example**
```asm
section .data
    signed_byte_neg    db  -25      ; 8-bit signed (Negative value)
    signed_byte_pos    db  40       ; 8-bit signed (Positive value)

    signed_word_neg    dw  -1000    ; 16-bit signed (Negative value)
    signed_word_pos    dw  3000     ; 16-bit signed (Positive value)
```

In assembly, **signed numbers** are usually represented using **two’s complement** encoding:
- The most significant bit (highest bit) indicates the sign: `0` for positive, `1` for negative.


### Why it Matters
- The CPU interprets bit patterns differently based on whether an instruction operates on signed or unsigned data.

    **Example:** When dividing 0xFF (255 unsigned, -1 signed) by two, we use different commands based on the value type. For unsigned division, we use the `div` command, resulting in 0x7F (255 ÷ 2 = 127). For signed division, we use the `idiv` command, resulting in 0x00 (-1 ÷ 2 = 0).



- Arithmetic operations like division, extension, or comparison use the sign to determine the result.

>[!NOTE]
> When moving a smaller value into a larger register (e.g., a `byte` into a `word`), the value must be **extended**.  
> - **Zero extension**: fills new bits with zeros for unsigned numbers.  
> - **Sign extension**: duplicates the sign bit for signed numbers.


## Declaring Data (Variables) in Assembly
A **variable** is a named memory location that your program can use to store and retrieve values. Variables are typically declared and initialized in the **data section** of your program.

**Syntax**
```
variable-name   define-directive   initial-value
```
- `variable-name`: The name (identifier) you assign to a memory address.
- The assembler assigns a unique offset to each variable within the data segment.

### Define Directives
The most common define directives are:

| Directive | Purpose | Storage Space |
|-----------|---------|--------------|
| `DB`      | Define Byte         | Allocates 1 byte  |
| `DW`      | Define Word         | Allocates 2 bytes |
| `DD`      | Define Double Word  | Allocates 4 bytes |

**Example** 
```asm
section .data
    my_byte   db   10        ; db = define byte, initializes with 10
    my_word   dw   1000      ; dw = define word, initializes with 1000
    my_dword  dd   12345678  ; dd = define double word, initializes with 12345678
```

### Constants
- A **constant** is a value that **never changes** during the program execution. 
- Declared with `equ` (equate) directive or by initializing a memory location that you never modify.

**Example** 
```asm
MAX_SIZE equ 100        ; Assembler will replace MAX_SIZE with 100 everywhere
```

## How Multibyte Data is Stored (Endianness)

When a data value is bigger than 1 byte (like a word, dword, or qword), it gets split into bytes in memory. `Endianness` is the order of these bytes:

- **Little Endian:** Least significant byte is stored first.
- **Big Endian:** Most significant byte is stored first.

**Example:** The value `0x12345678` as a 32-bit integer:

- **Little Endian:**
```
Address: [00] [01] [02] [03]
Value:   78   56   34   12
```
- **Big Endian:**
```
Address: [00] [01] [02] [03]
Value:   12   34   56   78
```

>[!NOTE]
> Intel/AMD (x86/x64) processors use little endian format by default.

### Why it Matters
- If you share data between different architectures or interpret raw memory/binary files, using the wrong endianness can cause bugs and confusing results.

## Data Alignment and Padding

**Alignment** ensures data is stored at memory addresses that are multiples of its size (for example, 4-byte data at addresses divisible by 4).

**Padding** is the insertion of unused bytes to achieve alignment.

 
### Why Align Data?
- Most processors can read/write aligned data faster.
- Misaligned data can result in reduced performance or even hardware exceptions.

**Example:** Placing a 4-byte integer after a 1-byte value
```asm
section .data
    myByte  db  0xAA              ; 1 byte
            db  0x00, 0x00, 0x00  ; 3 bytes padding (to align to 4-byte address)
    myInt   dd  0x12345678        ; 4 bytes, aligned at a 4-byte address
```

>[!NOTE]
> Most assemblers will automatically add padding, but manual alignment is sometimes needed.

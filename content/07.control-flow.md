# Control Flow

In assembly language programming, **control flow** is the process of deciding which instruction the CPU executes next. By default, instructions are executed sequentially from the first to the last. **Control flow** encompasses all the ways you can influence the program’s progression, including jumps, branches, loops, and function calls.


## Why Control Flow Matters

Without control flow, programs would only execute instructions in one fixed order, making them limited and inflexible. **Control flow lets you:**

- **Branch:** Skip over some instructions or jump to other sections.
- **Repeat:** Loop over instructions until a condition is met.
- **Decisid:** Choose actions based on data.
- **Organize:** Re-use blocks of code with functions/procedures.

## Types of Control Flow Instructions
Assembly languages use several instruction types to control the flow of execution, such as:
- ****Unconditional jumps** (`JMP`):** transfers execution directly to another part of the program.
  
     **Example**: `JMP`(jumps)
  
- **Conditional Jumps:** Transfers execution to another part if a specific condition is true.

     **Example**: `JE` (Jump if Equal), `JNE` (Jump if Not Equal), `JG` (Jump if Greater)
- **Procedure/Function Calls and Returns:** Manages functions.

     **Example**: `CALL` and `RET`
- **Loops:** Repeat a block of code multiple times.

Each of these instructions interacts with other elements, such as labels, the instruction pointer, and flags, to alter the program’s control flow.


## Labels
Assembly programs use **labels** as named targets for jumps and calls. They mark positions(addresses) in code.
- Jumps and calls use labels as their destination.
**syntax**
  
A label typically consists of an identifier followed by a colon (:).
```asm
label_name:    ; This is a label
    MOV EAX, 1 ; This is the instruction at that label's address
```
**Syntax Rules**
- **Characters**: You can use letters (A-Z, a-z), digits (0-9), and special characters like underscores (_), periods (.), or dollar signs ($).
- **Nameng**: Labels must start with a letter or an underscore (some assemblers also allow a period) and end with a colon (`:`) in most assemblers.
- **Case Sensitivity**: This depends on your assembler. NASM is case-sensitive (Loop: is different from loop:).
- **Reserved Words**: You cannot use instruction mnemonics (like MOV, PUSH) or register names (like EAX, RBX) as label names.

**Example**
```asm
start:
    mov eax, 1
    jmp next      ; jump to the label named 'next'
    mov eax, 2

next:
    mov eax, 3
```
`start:` and `next:` are **labels**. You can jump to them using jump instructions.

### local labels
A local label is defined by starting its name with a period (.). Its scope is tied to the last non-local label defined before it. NASM treats a local label as a sub-item of the preceding global label.
This allows you to reuse common names like .loop or .exit multiple times throughout your code, as long as they are under different global labels.

**Naming Rules**
- Starts with a dot: Must begin with . to be recognized as local.
- Valid Characters: Can contain letters, numbers, _, $, #, @, ~, and ?.
- No standalone dot: A label cannot be just a single period.
- Case Sensitivity: By default, labels in NASM are case-sensitive.

**Example**
```asm
label_one:              ; Global label
    mov ecx, 5
    .loop:             ; Local to label_one (Full name: label_one.loop)
        dec ecx
        jnz .loop      ; Jumps to label.loop

label_two:              ; New Global label (ends the scope of label_one)
    mov ecx, 10
    .loop:             ; Local to label_two (Full name: label.loop)
        dec ecx
        jnz .loop      ; Jumps to label_two.loop
```

## Instruction Pointers
The **EIP (Extended Instruction Pointer)** register always contains **the memory address of the instruction** that the CPU will execute next. When you jump to a label, call a function, or return from one, the value in EIP changes.

>[!NOTE]
> EIP is like a “bookmark” for the CPU—always pointing to “what’s next.” You *cannot* modify EIP directly, you must use jumps, calls, or returns to change it.


## Unconditional Jump
**Unconditional jumps** direct the CPU to continue execution always to a specific label/address instantly.
- **x86 mnemonic:** `JMP` 

**Syntax:**
```asm
JMP target_label
; code here is skipped!
target_label:
; execution resumes here
```

**Example**
```asm
    JMP next
    MOV eax, 1      ; This instruction is skipped
next:
    MOV eax, 2      ; Execution continues from here
```

## Conditional Jumps

**Conditional jumps** consider CPU flags to decide whether to jump. If the condition is true, the jump occurs. Otherwise, execution continues to the next instruction.

### Common Conditional Jump Instructions:
| Mnemonic | Meaning                  | Jump Condition |
|----------|--------------------------|:-------------:|
| JE/JZ    | Jump if Equal / Zero     | ZF = 1        |
| JNE/JNZ  | Jump if Not Equal/NotZero| ZF = 0        |
| JC       | Jump if Carry            | CF = 1        |
| JNC      | Jump if Not Carry        | CF = 0        |
| JA       | Jump if Above (unsigned) | CF=0, ZF=0    |
| JB       | Jump if Below (unsigned) | CF=1          |
| JG       | Jump if Greater (signed) | ZF=0, SF=OF   |
| JGE      | Jump if Greater or Equal (Signed)| SF=OF |
| JL       | Jump if Less (signed)    | SF!=OF        |
| JLE      | Jump if Less or Equal (signed)| ZF=1 or SF!=OF|

**Flags used:**  
- **ZF**: Zero flag  
- **CF**: Carry flag  
- **SF**: Sign flag  
- **OF**: Overflow flag

You **almost always** use this after a `CMP` or arithmetic instruction.


### **CMP Instruction**
`CMP` is commonly used to set the appropriate flags:
  ```asm
CMP eax, ebx   ; Sets flags based on (EAX - EBX)
JG  greater    ; Jumps if EAX > EBX (signed)
  ```
- Sets ZF if \(A = B\)
- Sets SF if the result is negative
- Sets CF if there is a borrow (A < B, unsigned)
- Sets OF if signed overflow


**Example**
```asm
    MOV eax, 5
    CMP eax, 10
    JL  less_than_10
    ; else block
less_than_10:
    ; code here
```

# System Calls

Assembly language is the closest human-readable representation of machine code. It provides direct control over a computer's hardware. It is often used in bootloaders and operating systems. System calls in Assembly allow programs to request services from the operating system, such as input/output, process management, and file operations.


## What Are System Calls?

System calls are **requests from a user program to the operating system kernel** to perform tasks the program cannot do directly (such as accessing hardware, files, or memory management). They act as an interface between user-level programs and the operating system. In x86-32 Linux assembly, you call the kernel using the `int 0x80` instruction. 

When a program makes a system call, it switches from user mode to kernel mode, allowing the program to execute privileged operations safely, such as interacting with hardware or managing processes.

## How System Calls Work in x86-32

1. **Load the syscall number** into the `eax` register. Each system call has a unique identifier. For example, `1` is for `exit`, `3` is for `read`, and `4` is for `write`.
2. **Load arguments** into registers:
   - `ebx`: 1st argument.
   - `ecx`: 2nd argument.
   - `edx`: 3rd argument.
   - `esi`: 4th argument.
   - `edi`: 5th argument.  
   - `ebp`: 6th argument.
3. **Trigger the system call** using the `int 0x80` instruction, which interrupts the CPU and transfers control to the kernel.
4. **Read the return value:**  
   - If successful, `eax` holds the return value.
   - If there’s an error, `eax` contains a negative value (the *error number*).

## Most Common System Calls (x86-32 Linux)

| Name     | Syscall # | Parameters                           | Description                     |
|----------|-----------|---------------------------------------|---------------------------------|
| `exit`   | 1         | `int status`                         | Exit the program.               |
| `read`   | 3         | `int fd, char *buf, size_t count`    | Read from a file or input.      |
| `write`  | 4         | `int fd, const char *buf, size_t count` | Write to a file or output.      |
| `open`   | 5         | `const char *filename, int flags`    | Open a file.                    |
| `close`  | 6         | `int fd`                             | Close an open file descriptor.  |
| `execve` | 11        | `const char *filename, char *const argv[], char *const envp[]` | Execute a new program. |
| `fork`   | 2         | None                                 | Create a new child process.     |
| `getpid` | 20        | None                                 | Get the process ID.             |

See the full list of system calls using:
```bash
man 2 syscalls
man 2 <syscall_name>
```
### Example
Writing 'A' to the terminal using the **write syscall**.
```asm
section .data
char db 'A'

section .text
    global _start

_start:
mov  eax, 4      ; Syscall number for write
mov  ebx, 1      ; Argument 1 : File descriptor 1 stdout (the screen).
mov  ecx, char   ; Argument 2 : Pointer to the data (the character to print).
mov  edx, 1      ; Argument 3 : Length of the data.
int  0x80        ; Trigger the system call

mov  eax, 1      ; Syscall number for exit
xor  ebx, ebx    ; Exit code 0
int 0x80         ; Trigger the system call

```
**Output**:
```
A
```
- This example demonstrates how the program asks the OS to write one character (`'A'`) to standard output and then exit.


## Input and Output (I/O) 

**Input and Output (I/O)** means communicating and interacting with external devices like keyboards, monitors, printers, etc. I/O is typically managed using system calls (for high-level OS interaction) or port-mapped I/O (for direct hardware communication).


### 1. High-Level OS Interaction (System Calls)
Most modern assembly programs use **system calls** to handle I/O, such as reading input from a keyboard or writing output to the console or screen.

**Standard File Descriptors**
- `stdin`**standard input device**: Where the program gets data, usually the keyboard, file descriptor `0`. 
- `stdout`**standard output device**: Where the program sends data, usually the screen, file descriptor `1`.
- `stderr`**standard error**:Where the program reports issues, file descriptor `2`.

> [!NOTE]
> A File Descriptor (FD) is a unique integer ID (0, 1, 2, etc.) that an operating system uses to track an open file or resource. Think of it as a "handle" or a "ticket number" for a stream of data. Instead of using a long file path, the system refers to the resource by its number.


**Examples:**
- This program prints "Hello, World!" to the terminal
```asm
section .data
    msg db 'Hello, World!', 0xA   ; 0xA = newline
    len equ $ - msg               ; Length of the string

section .text
    global _start

_start:
    ; write(1, msg, len)
    mov eax, 4         ; Syscall #4 = sys_write
    mov ebx, 1         ; File descriptor 1 = stdout
    mov ecx, msg       ; Pointer to message
    mov edx, len       ; Length of message
    int 0x80           ; Trigger the system call

    ; exit(0)
    mov eax, 1         ; Syscall #1 = sys_exit
    xor ebx, ebx       ; Exit code 0
    int 0x80           ; Trigger the system call
```

- `msg` contains the string "Hello, World!" followed by a newline (`0xA`).
- `len` calculates the length of the string automatically.

**Output:**
```
Hello, World!
```

- This program reads up to 32 characters from stdin (keyboard) and echoes them back to the screen.
```asm
section .bss
    buffer resb 32                ; Reserve 32 bytes for input

section .text
    global _start

_start:
    ; read(0, buffer, 32)
    mov eax, 3         ; Syscall #3 = sys_read
    mov ebx, 0         ; File descriptor 0 = stdin
    mov ecx, buffer    ; Pointer to buffer
    mov edx, 32        ; Number of bytes to read
    int 0x80           ; Trigger the system call

    mov edx, eax       ; actual bytes read are returned in eax

    ; write(1, buffer, edx)
    mov eax, 4         ; Syscall #4 = sys_write
    mov ebx, 1         ; File descriptor 1 = stdout
    mov ecx, buffer    ; Pointer to buffer
    int 0x80           ; Trigger the system call

    ; exit(0)
    mov eax, 1         ; Syscall #1 = sys_exit
    xor ebx, ebx       ; Exit code 0
    int 0x80           ; Trigger the system call

```
- `section .bss`: Declares uninitialized space for reserving memory for `buffer`.
- `buffer`: A location in memory to store user input.

**Output**
```
Input: Hello, NASM!
Output: Hello, NASM!
```

> [!important]
> System calls vary based on the operating system (e.g., Linux, Windows).


### 2. Direct Hardware Access (Port-Mapped I/O)
I/O ports are used to communicate directly with hardware devices. This involves instructions like `IN` and `OUT` to read from or write to specific ports.
This method is more common in low-level embedded systems or older computer systems.

**Example:**
- This program reads a byte from port 0x60 and writes it to port 0x64
```asm
section .text
    global _start

_start:
    mov edx, 0x60        ; Port address 0x60
    in  al, dx           ; Read a byte from port 0x60 into AL

    mov edx, 0x64        ; Port address 0x64
    out dx, al           ; Write the byte in AL to port 0x64

    ;exit(0)
    mov  eax, 1           ; Syscall #1 = sys_exit
    xor  ebx, ebx         ; Exit code 0
    int  0x80             ; Trigger the system call
```

- `in` and `out`: On x86, these instructions operate only on `al`, `ax`, or `eax`. Even in 32-bit mode, you still use `al` to move a single byte.

>[!NOTE]
> Port-mapped I/O is rarely used in modern operating systems but is common in embedded systems.

## File Operations
File operations in x86-32 assembly involve using system calls like `open`, `read`, `write`, and `close`. These syscalls allow you to interact with files on the filesystem.

**Examples:**

- This program writes the string "Hello, File!" to a file named `output.txt`.

```asm
section .data
    filename db 'output.txt', 0     ; File name (null-terminated)
    message db 'Hello, File!', 0xA  ; Message to write (with newline)
    len equ $ - message             ; Length of the message

section .text
    global _start

_start:
    ; open(filename, O_WRONLY | O_CREAT, 0644)
    mov eax, 5         ; Syscall #5 = sys_open
    mov ebx, filename  ; Pointer to file name
    mov ecx, 0x401     ; Flags: O_WRONLY | O_CREAT (octal 401)
    mov edx, 0644      ; Permissions: rw-r--r-- (octal 644)
    int 0x80           ; Trigger the system call
    mov ebx, eax       ; Save file descriptor in EBX

    ; write(fd, message, len)
    mov eax, 4         ; Syscall #4 = sys_write
    mov ecx, message   ; Pointer to message
    mov edx, len       ; Length of the message
    int 0x80           ; Trigger the system call

    ; close(fd)
    mov eax, 6         ; Syscall #6 = sys_close
    int 0x80           ; Trigger the system call

    ; exit(0)
    mov eax, 1         ; Syscall #1 = sys_exit
    xor ebx, ebx       ; Exit code 0
    int 0x80           ; Trigger the system call
```

- This program reads the contents of a file named `input.txt` and displays it on the screen.

```asm
section .data
    filename db 'input.txt', 0      ; File name (null-terminated)

section .bss
    buffer resb 64                 ; Reserve 64 bytes for file data

section .text
    global _start

_start:
    ; open(filename, O_RDONLY)
    mov eax, 5         ; Syscall #5 = sys_open
    mov ebx, filename  ; Pointer to file name
    xor ecx, ecx       ; Flags: O_RDONLY (0)
    int 0x80           ; Trigger the system call
    mov ebx, eax       ; Save file descriptor in EBX

    ; read(fd, buffer, 64)
    mov eax, 3         ; Syscall #3 = sys_read
    mov ecx, buffer    ; Pointer to buffer
    mov edx, 64        ; Number of bytes to read
    int 0x80           ; Trigger the system call

    ; write(1, buffer, eax)
    mov eax, 4         ; Syscall #4 = sys_write
    mov ebx, 1         ; File descriptor 1 = stdout
    int 0x80           ; Trigger the system call

    ; close(fd)
    mov eax, 6         ; Syscall #6 = sys_close
    int 0x80           ; Trigger the system call

    ; exit(0)
    mov eax, 1         ; Syscall #1 = sys_exit
    xor ebx, ebx       ; Exit code 0
    int 0x80           ; Trigger the system call
```

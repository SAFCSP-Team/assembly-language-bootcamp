# Control Flow

In Assembly programming language, **control flow** refers to the ways you influence which instruction the CPU executes next. By default, instructions run sequentially, but you can change the order using jumps, branches, loops, and function calls.

## Why Control Flow is Important
Without control flow, programs could only run in a fixed sequence, making them limited and inflexible. Control flow allows you to:
- **Branch:** Skip instructions or jump to different parts of code.
- **Repeat:** Loop over instructions until a condition is met.
- **Decide:** Execute actions based on data and conditions.
- **Organize:** Structure code into reusable functions or procedures.

## Types of Control Flow Instructions
Assembly languages provide several instruction types to control the flow of execution:

- ****Unconditional jumps**:** Immediately transfer execution to another part of the program.
  
     **Example**: `jmp target_label`
  
- **Conditional Jumps:** Transfers execution to another part if a specific condition is true (based on CPU flags).

     **Example**: `je` (Jump if Equal), `jne` (Jump if Not Equal), `jg` (Jump if Greater)

- **Loops:** Repeatedly execute a section of code, typically managed with counters and jumps.

     **Example**: `loop loop_label`

- **Calls and Returns:**  Change control flow to a function or procedure, then return to continue execution.  

     **Example**: `call` and `ret`

Each instruction interacts with program elements like labels, the instruction pointer, and status flags.


## Labels
Labels mark positions (addresses) in assembly code as targets for jumps or calls.

**Syntax:**
```asm
label_name:    ; Defines a label
    mov eax, 1 ; Instruction at this label
```

**Rules:**
- Must start with a letter, or underscore, and some assemblers also allow a period. They should end with a colon (`:`).
- Can use letters, digits, underscores (`_`), periods (`.`), or dollar signs (`$`).
- Cannot use reserved words (e.g., instruction names, register names).
- Some assemblers, such as NASM, are case-sensitive with label names( "Loop:" is different from "loop:").

**Example**
```asm
start:
    mov eax, 1
    jmp next      ; jump to the label named 'next'
    mov eax, 2

next:
    mov eax, 3
```
`start:` and `next:` are **labels**. You can jump to them using jump instructions.


### Local Labels
Local labels help organize code blocks. In NASM, they start with a period (`.`) and are scoped to the previous global label. This allows you to reuse common names like `.loop` or `.exit` multiple times throughout your code, as long as they are under different global labels.

**Rules:**
- Begin with a dot (`.`).
- Can contain letters, digits, `_`, `$`, `#`, `@`, `~`, and `?`.
- Cannot consist of just a single dot.

**Example**
```asm
label_one:              ; Global label
    mov ecx, 5
    .loop:             ; Local to label_one (Full name: label_one.loop)
        dec ecx
        jnz .loop      ; Jumps to label.loop

label_two:              ; New Global label (ends the scope of label_one)
    mov ecx, 10
    .loop:             ; Local to label_two (Full name: label.loop)
        dec ecx
        jnz .loop      ; Jumps to label_two.loop
```

## Unconditional Jump
`jmp` instruction causes the CPU to immediately jump to a specific label.

**Syntax:**
```asm
jmp target_label
; code here is skipped
target_label:
; execution resumes here
```

**Example**
```asm
    jmp next
    mov eax, 1      ; This instruction is skipped
next:
    mov eax, 2      ; Execution continues from here
```

## Conditional Jumps
Conditional jumps evaluate CPU flags to determine whether to jump. If the condition is true, the jump occurs. Otherwise, execution continues to the next instruction.

| Mnemonic  | Meaning                      | Jump Condition     |
|-----------|------------------------------|-------------------|
| je/jz     | Jump if Equal / Zero         | zf = 1            |
| jne/jnz   | Jump if Not Equal / Not Zero | zf = 0            |
| jc        | Jump if Carry                | cf = 1            |
| jnc       | Jump if Not Carry            | cf = 0            |
| ja        | Jump if Above (unsigned)     | cf = 0, zf = 0    |
| jb        | Jump if Below (unsigned)     | cf = 1            |
| jg        | Jump if Greater (signed)     | zf = 0, sf = of   |
| jge       | Jump if Greater or Equal     | sf = of           |
| jl        | Jump if Less (signed)        | sf != of           |
| jle       | Jump if Less or Equal        | zf = 1 or sf != of |

- **zf**: Zero flag  
- **cf**: Carry flag  
- **sf**: Sign flag  
- **of**: Overflow flag


Conditional jumps typically occur after a `cmp` (compare) or arithmetic instruction.


### `cmp` Instruction
`cmp` subtracts the second operand from the first and sets the CPU flags accordingly (without storing the result).

  ```asm
cmp eax, ebx   ; Sets flags based on (eax - ebx)
jg  greater    ; Jumps if eax > ebx (signed)
  ```
- Sets `zf` if (A = B)
- Sets `sf` if the result is negative
- Sets `cf` if there is a borrow (A < B, unsigned)
- Sets `of` if signed overflow

## Loops
Looping is foundational to programming and is used to repeat operations. Unlike high-level languages, assembly doesn't have built-in `for` or `while` statements. Loops are created manually using counters and jump instructions.


### Manual While Loop

This approach simulates a `while` loop by explicitly checking a condition at the top and jumping back if the loop should repeat.

```asm
    mov ecx, 10        ; Set loop counter to 10

loop_start:
    cmp ecx, 0         ; Check condition ecx <= 0  
    jle loop_end       ; Exit if counter <= 0

    ; --- loop body ---

    dec ecx            ; Decrement counter
    jmp loop_start     ; Repeat jump if Not Zero (ecx != 0)

loop_end:
```

### For Loop
A `for` loop can be simulated by initializing a counter and incrementing it repeatedly, returning to the beginning if the end condition is not met.
```asm
    mov ecx, 0          ; Start value
    mov ebx, 10         ; End value

for_loop:
    cmp ecx, ebx
    jge end_for          ; Exit if ecx >= ebx

    ; --- loop body ---

    inc ecx
    jmp for_loop

end_for:
```

### Using the `loop` Instruction (x86)
The x86 architecture provides the  `loop` instruction, which decrements the register `ecx` and, if `ecx` is not zero, jumps to the named label. 
```asm
    mov ecx, 5

myloop:
    ; --- loop body ---
    loop myloop   ; dec ecx, jump if ecx != 0
```

## Procedure/Function Calls and Returns

Functions (or procedures) allow you to structure programs into logically separate, reusable parts. Assembly language handles function calls using the stack for tracking return addresses.

### How Calls and Returns Work
- The `call` instruction pushes the return address (the next instruction’s address) onto the stack and jumps to the function's label.
- The `ret` instruction pops the return address off the stack and jumps back so the program continues after the original `CALL`.

**Syntax:**
```asm
call function_name
; ... execution resumes here after return

function_name:
    ; function code here
    ret
```

**Examples**
1. Function that doubles a value in eax
```asm
    mov eax, 7
    call double_it     ; Call the function
    ; eax now holds 14

    ; ... more code here ...

double_it:
    shl eax, 1         ; Multiply eax by 2 (shift left)
    ret
```
- You can call `double_it` from anywhere in your program.
- Any register or memory accessed in the "function" follows the normal rules.

2. Function with parameters and return value

```asm
    mov eax, 5
    mov ebx, 10
    call add_two_numbers
    ; eax = 15

    ; ...

add_two_numbers:
    add eax, ebx
    ret
```
- The function is called `add_two_numbers`.
- It takes two parameters: the first is `eax` and the second is `ebx`.
- The function returns the sum of `eax` and `ebx`, stored in `eax`.

# Program Memory Layout (Process Layout
When you run any program (including assembly), it becomes a **process** in your computer’s memory. Understanding **how a process is organized in memory** is crucial for writing robust code and effectively working with variables, functions, and pointers.

### Why Learn the Program's Memory Layout?
- **Prevent memory corruption:** Understand which addresses your code can access and which ones to avoid.
- **Correct variable scoping:** Understand the difference between **global**, **local**, and **dynamic** data, and where they're stored.
- **Effective debugging:** Use memory addresses to analyze and fix errors.

## Segments

### Stack
- **Used for function call information**, local (temporary) variables, parameters, and return address.
- Grows **downward** (from high to low addresses).
- **Managed by hardware** automatically, it is allocated when a function is called and deallocated when the function exits.
- **Risk:** Stack overflow (e.g., infinite recursion or large allocations).

### Heap
- Used for dynamic memory allocation, where memory is allocated at runtime (`malloc` in C, or OS-specific syscalls).
- Grows **upward** (from low to high addresses).
- **Managed by the programmer** via system calls.
- **Risk:** Memory leaks if you forget to free unused blocks.
  
>[!NOTE]
> A memory leak occurs when allocated memory is no longer needed but hasn't been deallocated. This can affect computer performance by reducing the available memory space.


### Uninitialized data segment (.bss)
- Stores the uninitialized global/static variables (declared without an initial value).
- The operating system sets this to zero by default when the program starts.
- Fixed location throughout execution.

### Initialized data segment (.data)
- Stores the initialized global/static variables (assign a value at declaration by the programmer).
- Fixed location throughout execution.

### Read only (.rodata)
- Stores the string literals and constant data.
- In some systems merged into `.text`.
- Attempting to write causes a segmentation fault.
- Fixed location throughout execution.

### Code segment (.text)
- Contains the compiled program code (executable instructions).
- Usually, it is read-only to prevent accidental/intentional modification.
- Program entry point (e.g., `_start` or `main`) is located here.
- Fixed location throughout execution.


## Segments in NASM Assembly
In NASM, you explicitly use `sections` to place code and data into the right memory regions.

```asm
section .text        ; Executable code (instructions)
    global _start
    ... your code here ...

section .data        ; Initialized data
    message db "Hello, World!", 0x0A

section .bss         ; Uninitialized data
    buffer  resb 255       ; Reserve 255 bytes (all zeroed)

section .rodata      ; Read-only data (optional)
    ro_msg db "Read-only", 0
```
### How This Affects Your Programming
- Variables in `.data` or `.bss` are **global** and have **fixed addresses**.
- Stack variables are local and **managed using instructions** like `push` and `call`, rather than through explicit sections.
- Heap variables are **allocated/freed at runtime** via system calls.


## Practice 
The following NASM code stores variables in different sections and prints their addresses. This helps you see which regions variables belong to.

- **Save this as** `Segments.asm`, assemble, and run it.  

```asm
section .data
    val_data db 11
    newline db 0xA
    addrbuf db "00000000"

section .bss
    val_bss  resb 1

section .data
    val_ro  db 22

section .text
    global _start

_start:
    ; Print address of val_data (.data)
    lea eax, [val_data]
    call print_addr

    ; Print address of val_bss (.bss)
    lea eax, [val_bss]
    call print_addr

    ; Print address of val_ro (.rodata)
    lea eax, [val_ro]
    call print_addr

    ; Print the address of a local variable on the stack
    sub esp, 4              ; Allocate 4 bytes on stack
    lea eax, [esp]          ; Address of stack variable
    call print_addr
    add esp, 4              ; Clean up stack

    ; Exit program
    mov eax, 1
    xor ebx, ebx
    int 0x80

; --- Print helpers ---

; Print address in eax as 8 hex digits
print_addr:
    pushad
    mov edi, addrbuf
    mov ecx, 8
.print_loop:
    mov edx, eax
    shr edx, 28
    and edx, 0xF
    cmp dl, 10
    jl .is_digit
    add dl, 7
.is_digit:
    add dl, '0'
    mov [edi], dl
    inc edi
    shl eax, 4
    loop .print_loop
    mov eax, 4
    mov ebx, 1
    mov ecx, addrbuf
    mov edx, 8
    int 0x80
    call print_newline
    popad
    ret

print_newline:
    pushad
    mov eax, 4
    mov ebx, 1
    mov ecx, newline
    mov edx, 1
    int 0x80
    popad
    ret
```

- You should see different addresses for variables in `.data`, `.bss`, `.rodata`, and on the stack.
- You’ll see stack addresses *change* with each run (they’re dynamic), while data and bss addresses are usually fixed.

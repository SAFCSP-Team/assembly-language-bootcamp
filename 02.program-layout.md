## Program Layout (Process Layout)

When you run your assembly program (or any program), it becomes a **process** in your computer's memory. Understanding **how a process is laid out in memory** as it executes. This knowledge will make concepts like variable declaration, function calls, and pointer manipulation in assembly much clearer.


## Why Learn the Program (Process) Layout?
- **Prevent memory corruption:** Know what you can safely read/write and where not to touch!
- **Correct variable scoping:** Understand the difference between *global*, *local*, and *dynamic* data.
- **Effective debugging:** Use memory addresses to analyze and fix errors.


## The Program Layout (on Linux, Intel x86) in memory

## Segments

### Stack
- Used for function call management, including local (temporary) variables and function parameters.
- Grows downward (from high to low addresses).
- Risks: stack overflow if too large (e.g., infinite recursion).
- Managed by hardware automatically, it is allocated when a function is called and deallocated when the function exits.

### Heap
- Used for dynamic memory allocation, where memory is allocated at runtime (`malloc` in C, or OS-specific syscalls).
- Grows upward (from low to high addresses).
- Risks: memory leaks.
- Managed by system calls, including freeing allocated memory.

>[!NOTE]
> There is an issue called a memory leak, which happens when an allocated memory address is no longer needed but is not deallocated. It decreases the performance of the computer since there is less space to be used in the memory.

### Uninitialized data segment (.bss)
- Stores the uninitialized global/static variables (declared with size but no value).
- Set to zero by default at load time by the OS.
- Has a fixed memory location during the entire run.

### Initialized data segment (.data)
- Stores the initialized global/static variables (assign a value at declaration by the programmer).
- Has a fixed memory location during the entire run.

### Read only (.rodata)
- Stores the string literals and constant data.
- Sometimes merged into .text
- Attempting to write causes a segmentation fault.
- Has a fixed memory location during the entire run.

### Code segment (.text)
- Contains the executable machine code (compilation of your instructions).
- It’s typically read-only to prevent modification during execution
- Entry point (`_start` or `main`) located here.
- Has a fixed memory location during the entire run.

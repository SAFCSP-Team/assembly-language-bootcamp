# Introduction to Assembly Programming Language

Assembly language is a **low-level programming language** that allows direct communication with a computer's hardware. Unlike high-level languages such as Python or Java, assembly code is closely tied to the architecture of the CPU, enabling control over hardware resources.

## What is Assembly Language?
Assembly language is a **low-level programming language** designed for a specific CPU architecture (such as Intel x86, ARM, or MIPS). Unlike high-level languages such as Python or Java, which focus on abstract user-friendly instructions, assembly uses a human-friendly `mnemonics` (like `MOV`, `ADD`, or `JMP`) mapped almost one-to-one to the instructions that a processor understands internally.

Assembly language acts as a bridge between human-readable code and the binary machine code. Instead of writing complex binary or human abstract words, you use simpler words such as `MOV`, `ADD`, or `JMP` to control what the computer does, step by step. 

## Advantages of Assembly Language
- **High performance:** Write highly optimized and efficient programs.
- **Direct hardware access:** Perfect for writing device drivers, operating system kernels, and embedded software.
- **Small executable size:** Ideal for developing lightweight software for systems with limited resources.
- **Deep hardware understanding:** Learning assembly gives you deeper insights into how computers actually process instructions.
- **Reverse engineering:** Security researchers and reverse engineers use assembly to analyze software and malware at the lowest level.

## How Does Assembly Language Work?
1. **Write assembly source code**: Use a text editor to write the assembly instructions (mnemonics) and save it with a `.asm` extension (e.g., `hello.asm`).
2. **Assemble**: Use an `assembler` (such as NASM, MASM, or GAS) to convert assembly code into machine code, usually as an object file (`.o`).
3. **Link (Optional)**: If your program uses code from libraries or other files, the `linker` merges them into one executable.
4. **Execute**: The CPU reads and executes machine code instructions directly.
>[!Note]
> Assembly is specific to the computer's hardware, so a program written for one type of CPU will *not* automatically run on another. We focus on **Intel x86 (32-bit)** CPUs.

### Installing NASM
**Check if NASM is already installed:**
```bash
whereis nasm
```
- If the output is a path like `/usr/bin/nasm`, NASM is already installed.
- If you get only `nasm:`, you’ll need to install it.

**To install NASM (latest version):**

1. Visit the official [NASM Downloads page](https://www.nasm.us/).
2. Download the source archive (`nasm-<version>.tar.gz`) for Linux.
3. Unpack the archive:
```bash
tar xzf nasm-<version>.tar.gz
cd nasm-<version>
```
4. Prepare the build system:
```bash
./configure
```
5. Build (Compiles NASM from the source code):
```bash
make
```
6. Install:
```bash
sudo make install
```
This will also install related tools like `ndisasm` (a disassembler) and NASM manual pages.

## Running Your First Assembly Program

### Step 1: Write Your Code
Open your text editor, such as Vim, Nano, or VS Code, and paste the following code. This is an example of assembly code that prints "Hello, World!".
```asm
section .text
    global _start

_start:
    mov edx, len      ; Length of the string
    mov ecx, msg      ; Address of the message
    mov ebx, 1        ; File descriptor 1 = stdout
    mov eax, 4        ; syscall number 4 = sys_write
    int 0x80          ; Interrupt to request kernel service

    mov ebx, 0        ; exit code 0
    mov eax, 1        ; syscall number 1 = sys_exit
    int 0x80

section .data
    msg db "Hello, world!", 0xa
    len equ $ - msg
```
Save it as `hello.asm`.

### Step 2: Verify CPU Architecture
Before building, check your CPU type:
```bash
uname -m
```
Common outputs:
| Output     | Meaning                       |
|------------|------------------------------|
| x86_64     | 64-bit Intel/AMD CPU         |
| aarch64    | 64-bit ARM CPU               |
| i386/i686  | 32-bit Intel/AMD CPU         |
| armv7l     | 32-bit ARM CPU               |


If you're on 64-bit but targeting 32-bit code (as above), you can use a 32-bit emulator to avoid any errors.

#### Install QEMU (x86 emulator for running 32-bit code)
```bash
sudo apt install qemu-user-static
```

### Step 3: Assemble the Source File
```bash
nasm -f elf32 hello.asm -o hello.o
```
- `nasm`: the assembler program.
- `-f elf32`: generate an **ELF** (Executable and Linking Format) object file, 32-bit style.
- `hello.asm`: your input source file.
- `-o hello.o`: output file name (object file).

This creates a `.o` file containing your code, but it’s not executable by itself.

### Step 4: Link to Create the Executable

```bash
i686-linux-gnu-ld -m elf_i386 hello.o -o hello
```
- `i686-linux-gnu-ld`: the 32-bit linker (sometimes just `ld`, but this form is portable on 64-bit systems too).
- `-m elf_i386`: tells the linker to create a 32-bit (i386 architecture) Linux executable.
- `hello.o`: your object file from above.
- `-o hello`: output file name (the final executable program).

The linker resolves addresses, pulls in any required startup code or libraries, and produces an actual program you can run.

### Step 5: Run Your Program
- **Using QEMU if you’re on a non-32-bit system:**
```bash
qemu-i386 ./hello
```
- **On native 32-bit:**
```bash
./hello
```


### Expected Output:
```
Hello, world!
```

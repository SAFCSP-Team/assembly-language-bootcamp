# Introduction to Assembly Programming Language
Assembly language is a low-level programming language that provides a direct way to communicate with a computer's hardware. Unlike high-level languages (like Python or Java), assembly is close to the specific architecture of the computer's CPU.

## What is Assembly Language?
Assembly language is a **low-level** programming language designed to interact closely with a computer's hardware. Each computer architecture (e.g, Intel x86, ARM, or MIPS) has its own unique assembly language. Unlike high-level languages such as Python or Java, which focus on user-friendly commands and abstraction, assembly consists of mnemonic instructions that correspond almost directly to the binary machine code executed by the CPU.

Think of assembly as a translator between human instructions and the electronic signals the CPU understands. Instead of writing complex binary or human words, you use simpler words such as `MOV`, `ADD`, or `JMP` to control what the computer does, step by step. 

## Advantages of Assembly Language
- **High Performance**: Programs written in assembly can be highly optimized for speed and size, useful when system resources (like memory or processor speed) are limited.
- **Direct Hardware Control**: Assembly allows direct manipulation of hardware, useful for device drivers and embedded systems.
- **Small Executable Size**: Assembly code typically results in smaller programs, which is crucial for embedded systems.
- **Educational Value**: Learning assembly gives you deeper insights into how computers actually process instructions.
- **Reverse Engineering and Security**: Many security professionals and reverse engineers use assembly to analyze software or malware at the lowest level.

## How Assembly Language Works
Assembly language acts as a middle layer between human-readable code and the binary machine code understood by the CPU. Programs written in assembly use mnemonic instructions (like `MOV`, `ADD`, `JMP`), which are translated into machine code instructions by a program called an **assembler**.

**Workflow:**
1. **Write assembly code.**
2. **Assembling**: The assembly program is passed to an **assembler** (like NASM, MASM, or GAS), which translates the text-based instructions into machine code (the 1s and 0s the CPU can execute).
3. **Linking (Optional)**: If your program uses code from libraries or other files, a **linker** will combine them into a single executable.
4. **Execution**: The CPU reads and executes machine code instructions directly.

>[!Note]
> Assembly is specific to the computer's hardware, so a program written for one type of CPU will *not* automatically run on another.

### Installing NASM
If you select "Development Tools" while installing Linux, you may get NASM installed along with the Linux operating system, and you do not need to download and install it separately. To check whether you already have NASM installed, take the following steps:
1. Open a Linux terminal.
2. Type `whereis nasm` and press ENTER.

If it is already installed, then a line like nasm: /usr/bin/nasm appears. Otherwise, you will see just nasm:, then you need to install NASM.

**To install NASM, take the following steps**:
1. Check the [Netwide Assembler (NASM) website](https://www.nasm.us/) for the latest version.
2. Download the Linux source archive nasm-X.XX.ta.gz, where X.XX is the NASM version number in the archive.
3. Unpack the archive into a directory that creates a subdirectory nasm-X. XX.
4. Go to the nasm-X.XX folder and type ./configure. This shell script will find the best C compiler to use and set up Makefiles accordingly.
5. Type `make` to build the nasm and ndisasm binaries.
6. Type `make install` to install nasm and ndisasm in /usr/local/bin and to install the man pages.

## Components of Assembly Language

- **Registers**: Registers are small, fast memory locations within the CPU used to store data temporarily. Example: In x86, you have `AX`, `BX`, `CX`, etc.
- **Instructions/Mnemonics**: Human-readable commands representing CPU operations (`MOV`, `ADD`).
- **Memory Addressing**: Assembly lets you work directly with memory, accessing data at specific addresses.
- **Operands**: The data or addresses instructions operate on (could be registers, memory addresses, or immediate values).
- **Labels**: Named markers for specific points in the code, often used as point destinations you can access directly.
- **Directives**: Special keywords to the assembler *do not* translate to CPU instructions but control the assembly process (e.g., `.data`, `.code`).
- **Comments**: Explanations in code, ignored by the assembler, begin with a semicolon `;` or `#` depending on the syntax.

# Introduction to Assembly Programming Language
Assembly language is a low-level programming language that provides a direct way to communicate with a computer's hardware. Unlike high-level languages (like Python or Java), assembly is close to the specific architecture of the computer's CPU.

## What is Assembly Language?
Assembly language is a **low-level** programming language designed for a specific CPU architecture (like Intel x86, ARM, or MIPS). Unlike high-level languages such as Python or Java, which focus on user-friendly commands and abstraction, assembly gives you direct control over the hardware, using human-readable *mnemonics* (like `MOV`, `ADD`, or `JMP`) mapped almost one-to-one to the instructions that a processor understands internally.

Think of assembly as a middle layer between human-readable code and the binary machine code understood by the CPU. Instead of writing complex binary or human abstract words, you use simpler words such as `MOV`, `ADD`, or `JMP` to control what the computer does, step by step. 

## Advantages of Assembly Language
- **High Performance**: Write programs that are as fast and lightweight as possible.
- **Direct Hardware Control**: Assembly allows direct manipulation of hardware, useful for device drivers and embedded systems.
- **Small Executable Size**: Assembly code typically results in smaller programs, which is crucial for embedded systems.
- **Deeper Understanding**: Learning assembly gives you deeper insights into how computers actually process instructions.
- **Reverse Engineering and Security**: Security researchers and reverse engineers use assembly to analyze software and malware at the lowest level.

## How Assembly Language Works
1. **Write assembly code**: Use a text editor to write the assembly instructions (mnemonics) and save it with a `.asm` extension (e.g., `hello.asm`).
2. **Assembling**: The assembly program is passed to an **assembler** (like NASM, MASM, or GAS), which converts your code into machine code (the 1s and 0s) in an object file  with a `.o` extension.
3. **Linking (Optional)**: If your program uses code from libraries or other files, a **linker** will combine them into a single executable.
4. **Execution**: The CPU reads and executes machine code instructions directly.

>[!Note]
> Assembly is specific to the computer's hardware, so a program written for one type of CPU will *not* automatically run on another. We focus on 32-bit x86.

### Installing NASM
**Check if NASM is already installed:**
```bash
whereis nasm
```
- If you see a path like `/usr/bin/nasm`, NASM is already installed.
- If you get only `nasm:`, you’ll need to install it.

**To install NASM (latest version):**

1. Visit the official [NASM Downloads page](https://www.nasm.us/).
2. Download the source archive (`nasm-<version>.tar.gz`) for Linux.
3. Unpack the archive:
```bash
tar xzf nasm-<version>.tar.gz
cd nasm-<version>
```
4. Prepare the build system:
```bash
./configure
```
5. Build(compiles NASM from the source code):
```bash
make
```
6. Install:
```bash
sudo make install
```
This will also install related tools like `ndisasm` (a disassembler) and NASM manual pages.

## Building and Running Your First Assembly Program

**Step 1: Write Your Code**
Open your text editor, such as Vim, Nano, or VS Code, and paste the following code. This is an example of assembly code that prints "Hello, World!".
```asm
section .text
    global _start

_start:
    mov edx, len      ; Length of the string
    mov ecx, msg      ; Address of the message
    mov ebx, 1        ; File descriptor 1 = stdout
    mov eax, 4        ; syscall number 4 = sys_write
    int 0x80          ; Interrupt to request kernel service

    mov ebx, 0        ; exit code 0
    mov eax, 1        ; syscall number 1 = sys_exit
    int 0x80

section .data
    msg db "Hello, world!", 0xa
    len equ $ - msg
```

Save it as `hello.asm` in your home directory.


**Step 2: Check Your CPU Architecture**

Before building, check what kind of CPU you have:
```bash
uname -m
```
#### Common Outputs and Meanings

| Output     | Meaning                                                          |
|------------|------------------------------------------------------------------|
| x86_64     | 64-bit Intel or AMD (typical PC/server)                          |
| i386/i686  | 32-bit Intel (older PC, embedded)                                |
| aarch64    | 64-bit ARM (Apple Silicon, AWS Graviton, etc.) |
| armv7l     | 32-bit ARM (older RPi or IoT devices)                            |

If you're on 64-bit (`x86_64`) but targeting 32-bit code (as above), you need a 32-bit emulator.


#### Install QEMU (x86 emulator for running 32-bit code)
```bash
sudo apt install qemu-user-static
```


**Step 3: Assemble the Source File**

```bash
nasm -f elf32 hello.asm -o hello.o
```
- `nasm`: the assembler program.
- `-f elf32`: generate an **ELF** (Executable and Linking Format) object file, 32-bit style.
- `hello.asm`: your input source file.
- `-o hello.o`: output filename (object file).

This creates a `.o` file containing your code, but it’s not executable by itself.

**Step 4: Link the Object File to Create an Executable**

```bash
i686-linux-gnu-ld -m elf_i386 hello.o -o hello
```
- `i686-linux-gnu-ld`: the 32-bit linker (sometimes just `ld`, but this form is portable on 64-bit systems too).
- `-m elf_i386`: tells the linker to create a 32-bit (i386 architecture) Linux executable.
- `hello.o`: your object file from above.
- `-o hello`: output filename (the final executable program).

The linker resolves addresses, pulls in any required startup code or libraries, and produces an actual program you can run

**Step 5: Execute the code using QEMU**
```
qemu-i386 ./hello
```

#### Output
```
Hello, world!
```
